# Submodel-7 模块（副屏显示）

## 概述

本模块为辅助显示扩展方案，在主屏之外提供小型常显信息面板，用于展示设备状态、简易 LOGO 或通知提醒。本模块物理体积较大，占用两个 Submodel 插槽位置。

- **主控芯片**：CH32V103C8T6
- **屏幕规格**：2.13 寸全反屏（反射式液晶屏），分辨率 122×250
- **与核心模块接口**：模块侧 UART1，**230400/8-N-1**
- **模块 ID**：`0x40` ~ `0x42`
- **模块类型编号**：`0x05`
- **子类型编号**：`0x07`（Sub Display）
- **物理占用**：2 个 Submodel 插槽位置，占用 1 路 UART

## 硬件组成

- **CH32V103C8T6**：负责接收数据、管理显示内容、驱动屏幕刷新
- **2.13 寸全反屏**：122×250 分辨率，反射式液晶，无需背光，阳光越强光越清晰，极端低功耗
- **驱动芯片**：ST7305

## 软件职责

### 初始化阶段

- 初始化 CH32V103 时钟、GPIO、SPI、UART1（230400）
- 初始化全反屏驱动芯片：配置分辨率、扫描方向、刷新模式
- 向 Core 回复 `CMD_GET_TYPE`，上报子类型 `0x07`

### 运行阶段

- **GET_TYPE 心跳**：响应 Core 的 `CMD_GET_TYPE` 请求，上报子类型 `0x07`；
  同时以心跳计数作为全模块的计时基准（心跳约 500ms 一次）：每 6 次心跳（约 3s）
  在状态模式下自动翻页，每 30 次心跳（约 15s）向 Core 请求一次系统状态
- **三页轮显（状态模式）**：
  - **Page 0（Audio）**：音频播放状态、曲目名、音量/进度条、电量、蓝牙状态
  - **Page 1（System）**：存储设备/忙碌、Display 与 Keyboard 类型、RGB 模式/亮度、
    屏幕亮度、键盘背光、外接 HID 设备类型、配置加载状态
  - **Page 2（Modules）**：6 个槽位模块在线状态列表 + 键盘按键统计
- **图片模式**：显示 Core 下发的 BMP 图片（1bit 位图），固定显示不自动翻页；
  `SET_MODE SUB=0x04` 在状态/图片模式间切换
- **内容接收**：通过 UART1 接收 Core 下发的副屏内容指令
- **命令处理**：
  - `CMD_SUB_SET_MODE (0x41)`：接收状态数据、自定义内容、清屏、模式切换、BMP 文件名（SUB=0x05）、BMP/设备列表多帧传输
  - `CMD_SUB_GET_STATUS (0x42)`：向 Core 请求系统状态、设备列表、BMP 图片
  - `CMD_SUB_BULK_TRANSFER (0x46)`：接收 Bulk 模式图片数据（握手 + 多帧数据 + 完成确认）
- **BMP 图片传输**：向 Core 请求 `\BMP` 目录下的 BMP 文件，Core 解析为 1bit 位图后多帧传输
  （直接累积进 4KB 图片缓冲，122×250@1bpp = 4000 字节整屏）
- **屏幕刷新**：内容更新合并后统一刷新（`g_refresh_pending` 合并刷新标志），
  刷新完成后调用 `st7305_power_low()` 进入面板低功耗
- **低功耗管理**：全反屏静态显示不耗电，配合 ST7305 低功耗状态，适合常挂运行

### 中断与事件

- UART1 中断：接收 Core 的内容更新指令（ISR 直接喂协议状态机，双缓冲接收）

## 命名规范

- **文件**：统一采用下划线加小写字母，例如 `hardware.c`、`sub_display.h`
- **函数**：每个单词首字母大写加下划线，例如 `Hardware_Init()`、`SubDisp_Update()`
- **变量**：统一小写加下划线，例如 `disp_content`、`refresh_flag`
- **文件夹**：下划线写法，仅首字母大写，例如 `SubDisplay`、`Font`
- **系统目录**（`Core`、`Debug`、`Peripheral`、`Startup`）保持不动，不参与上述命名规范

## 布局规范（V1.1，122×250，font_montserrat_12：字高 15/基线 12）

重排后的固定布局常量（`app.h`），所有页面遵守，已消除历史上的重叠/溢出：

- **顶部状态栏**：0..19（黑底），电池图标 (2,5)+文字 x=20，蓝牙图标右对齐 y=3，音频图标居中 y=3
- **内容区**：y=24..233；行距 20px（Page0）/26px（Page1）/18px（Page2 模块行），
  文字行盒 15px、图标 ≤13px，行间留 4~5px 间隙
- **底部页码条**：234..249（高 16 黑底），文字 y=234，行盒恰好不出栏
- **列约定**：图标列 x=4（最宽图标 USB=16px 占 4..19），文字列统一 x=24，
  右对齐文字预留 `UI_GetStringWidth` + 4px 右边距；Page0 音量条 x=26 w=58（26..84）
  与右对齐百分比（≥88）不重叠；Page1 进度条列 x=60 w=58
- **Page2 底部按键统计**：分隔线 y=204，内容 y=208..227，不压页码条
- 图标绘制必须传真实宽高宏（`ICON_*_WIDTH/HEIGHT`），否则 `UI_DrawIcon`
  按错误行宽解位图会花图（play/mute 等曾统一传 12×12 的 bug 已修）

## 开发要点

1. **全反屏特性**：全反屏（Reflective LCD）无背光，依靠环境光反射显示，因此黑暗环境下不可见；若需在夜间使用，可考虑在模块上加装极小面积的前光（Front Light），但会牺牲部分功耗优势。
2. **分辨率限制**：122×250 像素极低，不适合复杂 UI；建议采用固定布局分区（如顶部状态栏、中部大字体时间、底部图标行），Core 下发时只需传递字段内容，无需传输整张位图。
3. **刷新速率**：全反屏刷新通常较慢（百毫秒级），且可能有闪烁；建议在收到 Core 指令后做内容合并（如 200 ms 内连续到达的多条更新合并为一帧），减少无效刷新。
4. **与主屏的协同**：副屏是主屏的补充而非替代。Core 侧在系统状态变化时主动向副屏推送；
   副屏自身每约 15s（30 次心跳）向 Core 拉取一次系统状态（音频/电量/蓝牙/模块在线等），
   主屏熄屏后副屏仍可保持显示。副屏也是整机"模块组成"的可视化窗口（Page 2 模块列表）。
5. **双槽位设计**：因占用 2 个 Submodel 位置，PCB 尺寸较大，布线时需注意与相邻模块的物理干涉；外壳设计预留足够空间。
6. **低功耗优势**：这是所有 Submodel 中最适合常挂运行的模块，整机休眠时可仅保留副屏显示基本信息；建议在 Power 模块的休眠策略中对此做特别考虑。
